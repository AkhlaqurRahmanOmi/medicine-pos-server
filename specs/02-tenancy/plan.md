## 1. Crate layout

```
crates/tenancy/
  src/
    lib.rs                  # pub mod access, commands, queries, platform, rest, perms
    access.rs               # AccessMode, the state rule, and the AccessModeSource impl
    commands.rs             # writes, take &Tx
    queries.rs              # reads, take &Db
    platform.rs             # platform-token writes — approve, suspend, confirm
    repo.rs                 # PRIVATE. All SQL and every entity use
    rest.rs                 # handlers, utoipa attributes, route registration
    perms.rs                # the permission slugs, &'static str
    types.rs                # API types — never a generated entity on the wire
    entity/                 # generated by sea-orm-cli, never hand-edited
```

`access.rs` is deliberately separate from `queries.rs`: it is the one thing every other
module depends on, it is pure given a `now` and a row, and keeping it alone makes it testable
without a database for every state but the lookup itself.

**Dependencies:** `core`, `db`, `api`, `cache`, `sea-orm`, `sqlx`, `rust_decimal`, `utoipa`,
`chrono`. No module crate, now or later — if tenancy ever needs identity, the flow belongs in
`09-workflows` `[D-97]`.

## 2. Migrations

`m0002_tenancy`, hand-written raw SQL in `crates/migration`, one file. **Written here, never
run by an agent** — Article V.

Order inside the file, because each step depends on the one before:

1. `CREATE EXTENSION IF NOT EXISTS btree_gist;` — the subscriptions exclusion constraint
   needs it, and the migration fails late and confusingly without it.
2. The four **platform** tables: `plans`, `plan_prices`, `plan_limit_types`, `plan_limits`.
   RLS enabled and forced, with a `USING (true)` read policy and a
   `WITH CHECK (current_setting('app.is_platform', true) = 'true')` write policy.
3. `tenants`, then `tenant_settings` (FK `tenant_id` → `tenants.id`), then `branches`.
4. `subscriptions`, with the composite FK `(plan_id, billing_period)` → `plan_prices` and the
   exclusion constraint.
5. `subscription_payments` — `tenant_id` nullable, `ON DELETE SET NULL`.
6. `tenant_exports`.
7. Policies, grants, and the indexes, all in this file. **A migration that creates a
   tenant-owned table without its policy is incomplete.**

Every tenant-owned table gets the standard pair:

```sql
ALTER TABLE <t> ENABLE ROW LEVEL SECURITY;
ALTER TABLE <t> FORCE ROW LEVEL SECURITY;

CREATE POLICY <t>_tenant ON <t>
  USING (tenant_id = app.current_tenant_id()
         OR current_setting('app.is_platform', true) = 'true')
  WITH CHECK (tenant_id = app.current_tenant_id()
         OR current_setting('app.is_platform', true) = 'true');
```

`tenants` is the one table whose policy compares `id`, not `tenant_id`.

**`app.is_platform` appears in this module's policies and nowhere else.** That is the whole
of the platform's cross-tenant read, and an assertion proves no other module's migration
mentions it.

Indexes lead with `tenant_id`, since every query is already filtered by it:
`(tenant_id, status)` on `subscriptions`, `(tenant_id, is_active)` on `branches`,
`(status, paid_at)` on `subscription_payments` for the platform's review queue.

### Seed, in the same migration

One plan, every limit unlimited `[D-89]`: a `plans` row, two `plan_prices` rows, three
`plan_limit_types` rows, and three `plan_limits` rows with `max_value = NULL`. Without the
seed, `[AC-U09]` is vacuously true and the limit check is never exercised.

## 3. Types

```rust
// access.rs
pub enum AccessMode { Blocked(BlockReason), ReadOnly, Full, FullWithWarning { until: DateTime<Utc> } }
pub enum BlockReason { PendingApproval, Suspended }

/// Everything the rule needs, so the decision is pure and table-driven in tests.
pub struct AccessFacts {
    pub status: TenantStatus,
    pub covering: Option<SubscriptionWindow>,  // the subscription covering `now`, if any
    pub latest_end: Option<DateTime<Utc>>,     // ends_at of the most recent subscription
    pub grace_days: i32,
}

pub fn decide(facts: &AccessFacts, now: DateTime<Utc>) -> AccessMode;

// types.rs — on the wire. snake_case, money as string, never a generated entity.
pub struct Tenant { id, name, legal_name, vat_bin, phone, email, status, access: AccessSummary }
pub struct AccessSummary { mode: &'static str, warning_until: Option<DateTime<Utc>> }
pub struct Branch { id, name, address, phone, drug_license_no, is_default, is_active }
pub struct TenantSettings { vat_rate: Decimal, vat_included: bool, rounding_mode, … }
pub struct Subscription { id, plan_code, billing_period, price: Decimal, starts_at, ends_at, status, is_complimentary }
pub struct Payment { id, subscription_id, amount: Decimal, method, reference, status, paid_at }
```

`vat_rate` and every amount are `rust_decimal::Decimal`, serialised as strings. A float here
reaches a receipt.

`AccessSummary` is returned on `GET /tenant` so the app can draw its renewal banner without a
second call — the warning the guide's `update_available` flag does for app versions.

## 4. Commands

| Command | Signature | Transaction boundary |
|---|---|---|
| `create_branch` | `(&Tx, NewBranch) -> Branch` | one. Checks the `branches` limit inside it, so two concurrent creates cannot both pass |
| `deactivate_branch` | `(&Tx, BranchId) -> Branch` | one. Refuses the default or the last active branch |
| `update_settings` | `(&Tx, SettingsPatch) -> TenantSettings` | one. Partial — every field optional |
| `submit_payment` | `(&Tx, NewPayment) -> Payment` | one. Forces `status = submitted`; the caller cannot choose |
| `request_closure` | `(&Tx, UserId) -> Tenant` | one |
| `approve` · `suspend` · `reinstate` | `(&Tx, TenantId, …) -> Tenant` | one each, platform only |
| `confirm_payment` | `(&Tx, PaymentId) -> (Payment, Subscription)` | **one transaction for both.** Confirming is what activates the subscription `[AC-E07]`; two transactions could confirm a payment against no subscription |
| `create_subscription` | `(&Tx, NewSubscription) -> Subscription` | one. The overlap is caught by the exclusion constraint, and the error is mapped, not pre-checked |

**No command pre-checks what a constraint already enforces.** `create_subscription` attempts
the insert and maps `23P01` (exclusion violation) to `409 subscription_overlap`; a `SELECT`
first would still race.

## 5. Queries

| Query | Signature | Notes |
|---|---|---|
| `access_mode` | `(&Db, TenantId, now) -> AccessMode` | One query for the facts, then `decide`. Cached — see below |
| `tenant` · `settings` | `(&Db, TenantId) -> …` | — |
| `branches` | `(&Db, TenantId, Pagination) -> ListPage<Branch>` | Cursor on `id`, UUIDv7 |
| `limit_remaining` | `(&Db, TenantId, &str) -> Option<i32>` | `None` is unlimited. One shared rule for every limit `[D-89]` |
| `plans` | `(&Db) -> Vec<Plan>` | No `tenant_id` in the query at all |
| `payments_for_review` | `(&Db, status, Pagination)` | Platform only. Requires `app.is_platform` |

**Caching.** `access_mode` runs on every request, so it is cached in Redis beside branch
access, keyed `tenant:{id}:access`, TTL 60s, and **invalidated explicitly** by `approve`,
`suspend`, `reinstate`, `confirm_payment` and `create_subscription`. The TTL is the backstop,
not the mechanism: a suspension must bite immediately, not in a minute.

A cache miss or a Redis outage falls back to the database. It never falls back to **Full** —
if neither Redis nor Postgres can answer, the request fails with `500`, because guessing
"allowed" is how a suspended pharmacy keeps trading.

## 7. Risks

| Risk | Why it is plausible | Mitigation |
|---|---|---|
| **`app.is_platform` becomes a general-purpose bypass** | It is a session variable any migration could read, and it would "work" | It appears in this module's policies only, asserted by a grep across `crates/migration`. A platform token reaching a sale is then a 404, not a leak |
| `Tx::begin_platform` is used from a pharmacy request | One wrong call site makes every policy permissive | It takes a platform token type `03-identity` has not built yet; until then it is `pub(crate)` and used only by `platform.rs`, which `rest.rs` reaches only behind the admin router |
| A stale cached access mode lets a suspended pharmacy trade | The cache exists precisely to avoid the query | Explicit invalidation on every status and subscription write; 60s TTL as a backstop; no fallback to **Full** |
| The exclusion constraint is written without `btree_gist` | The extension is easy to forget and the error is opaque | Step 1 of the migration, and a test that inserts an overlapping row |
| Access mode is computed in two places | `api`'s gate needs it and `rest.rs` returns it | One function, `decide`, taking facts. The gate and the handler both call it |
| Purge deletes payments | `ON DELETE CASCADE` is the default habit | `ON DELETE SET NULL` on that one FK, with a test that proves the row survives |
